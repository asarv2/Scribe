# Slide 11

**Grouping**

Often we want the result to provide more information that just whether we found a match or not
For example, we may operate on only part of the text that matched
Groupings are used for this. Enclose portions of the regular expression in parentheses to access them via groups

```
sen = "This is a test that tests regular expression basics for numbers 1234 and letters A-Z."
pattern = re.compile(r"(\d+)\s+")
for match in re.finditer(pattern, sen):
    print("'" + match.group(0) + "'")   # full match'
    print("'" + match.group(1) + "'")   # first group'
'1234 '
'1234'
```

---

**Description:**

This slide, part of the Intro to Data Science lecture, demonstrates how to use grouping in regular expressions to extract specific parts of a matched string.  The example shows how to extract the numerical part of a string containing both numbers and text.

*   **`sen`:** This variable holds the input string, which contains a sentence with numbers and letters.

*   **`pattern = re.compile(r"(\d+)\s+")`:** This line defines the regular expression pattern.  Crucially, the parentheses `()` around `\d+` create a *capturing group*.  This means that the regular expression engine will remember the portion of the string that matched this group.  The `\s+` matches one or more whitespace characters after the digits.

*   **`for match in re.finditer(pattern, sen):`:** This loop iterates through all matches of the pattern in the string.

*   **`print("'" + match.group(0) + "'")`:** This line prints the *full match*, which includes the digits and the following whitespace.

*   **`print("'" + match.group(1) + "'")`:** This line prints the *first capturing group*, which is just the sequence of digits (`\d+`).

*   **Output:** The output shows that the code correctly extracts the digits "1234" from the input string.  The first `print` statement shows the full match, including the space after the numbers. The second `print` statement shows only the digits.

The slide illustrates the use of capturing groups to extract specific parts of a matched string, which is a powerful technique for data extraction and manipulation in data science. The comments `# full match'` and `# first group'` are helpful annotations to understand the purpose of each `print` statement.


# Slide 12

**Order of operations**

There is an order of operations in regular expressions

*   `abc|def` matches the strings "abc" or "def", not "ab(c or d)ef"
*   You can get around this using parenthesis e.g., a(bc|de)f

By default, regular expressions try to capture as much text as possible (greedy matching)

*   `<(.*)>` applied to `<tag>text</tag>` will match the entire expression
*   If you want to capture the least amount of text possible use `<(.*?)>`
the ? makes the matching lazy rather than greedy will just match the `<a>` term


---

**Description:**

This slide, part of the Intro to Data Science course, discusses the order of operations in regular expressions (regex) and how to control the matching behavior.

*   **Order of Operations:** The first bullet point explains that regex operators have a specific order of execution.  The example `abc|def` illustrates that the `|` (OR) operator has lower precedence than the other operators.  This means that `abc|def` will match either "abc" or "def", but not "ab(c or d)ef".

*   **Parentheses for Grouping:** The second bullet point explains how parentheses can be used to change the order of operations and create capturing groups.  The example `a(bc|de)f` shows how parentheses force the `|` operator to apply to the `bc` or `de` parts, allowing the regex to match "abcf" or "adef".

*   **Greedy Matching:** The next section explains that by default, regex engines are "greedy," meaning they try to match as much text as possible.  The example `<(.*)>` applied to `<tag>text</tag>` illustrates this.  The `(.*)` part will match the entire string between the `<tag>` and `</tag>` tags, not just the first `<tag>`.

*   **Lazy Matching:** The final bullet point introduces the concept of "lazy" matching.  The example `<(.*?)>` shows how to use the `?` quantifier to make the matching lazy, meaning it will match the *least* amount of text possible.  The example `<(.*?)>` applied to `<tag>text</tag>` will only match the `<a>` part.

The slide is crucial for understanding how to control the behavior of regex matches, especially when dealing with complex patterns in text data.  The examples are clear and illustrate the differences between greedy and lazy matching.

# Slide 25

**TFIDF**

A simple 'bag of words' model of documents

TF: Term Frequency
for each term in each document, the number of times the word occurs divided by the number of the words in the document

IDF: Inverse Document Frequency
for each term across the corpus: ln(N / (1 + n<sub>t</sub>))
where N is the number of documents, and n<sub>t</sub> is the number of documents that contain the term

TFIDF: Multiply TF by IDF to get a sense of words more unique in a document

ln(100/101) = -0.00995
ln(100/50) = 0.6931
ln(100/10) = 2.3


**Description of the Slide:**

It explains the concepts of Term Frequency (TF) and Inverse Document Frequency (IDF) in the context of a "bag of words" model for documents.
