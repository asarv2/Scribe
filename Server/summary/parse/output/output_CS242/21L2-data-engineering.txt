# Slide 10

# MapReduce

Programming model for data-intensive computing on commodity clusters
A simple paradigm for distributed computation where users write just two functions:

* **mapper:** An applied function to generate intermediate data
* **reducer:** A function that combines and simplifies the intermediate date appropriately

Work can be automatically farmed out to a large collection of machines
* As much as possible, computation is done on the machine where the data lives
* Node failures or "stragglers" (nodes that are slow for any reason) are automatically handled

# Slide 12

# Example

**Example:** sum charges for each credit card

```
procedure MAPCREDITCARDS(input)
  while not input.done() do
    record ← input.next()
    card ← record.card
    amount ← record.amount
    Emit(card, amount)
  end while
end procedure

procedure REDUCE CREDITCARDS(key, values)
  total ← 0
  card ← key
  while not values.done() do
    amount ← values.next()
    total ← total + amount
  end while
  Emit(card, total)
end procedure
```

**Key:** Card number
**Value:** Charge on card
**Key:** Card number
**Output:** Sum of charges

# Slide 13

# Abstracting map+reduce

Process can be decomposed into to the mapper function, the reducer function and the
execution engine (the supporting code that actually calls the map and reduce functions)

To use this framework, the programmer only needs to implement the mapper and the
reducer function—the execution engine can use whatever method it wants to actually
compute the result

The mapper function is inherently parallel, allowing execution in separate threads/machines

In many cases, the reduce step can also be carried out incrementally


---

It explains that the MapReduce process can be broken down into three components: the mapper function, the reducer function, and the execution engine.  The programmer only needs to implement the mapper and reducer functions; the execution engine handles the details of distributing the work and combining the results.  The slide emphasizes the inherent parallelism of the mapper function, which allows for efficient execution across multiple threads or machines. # Slide 14

# MapReduce

**Basic process**

* **Map:** transforms data records into pairs, each with a key and a value
* **Shuffle:** uses a hash function so that all pairs with the same key end up next to each other and on the same machine
* **Reduce:** processes records in batches, where all pairs with the same key are processed at the same time

Idempotence of Mapper and Reducer provides fault tolerance
* multiple operations on same input gives same output


---

**Description of the slide:**

This slide, part of a lecture on Intro to Data Science, describes the basic MapReduce process.  It outlines the three key steps: Map, Shuffle, and Reduce.  The slide explains how the Map step transforms data into key-value pairs, the Shuffle step groups these pairs by key, and the Reduce step processes the grouped data.  The slide also mentions the importance of idempotence in MapReduce for fault tolerance, meaning that multiple operations on the same input will produce the same output.  There are no figures on this slide.  The content is entirely text-based, focusing on the description of the MapReduce process.

map(f, [a, b, c, ...]) -> [f(a), f(b), f(c), ...]
