# Slide 34

From Python map+reduce to MapReduce
You can think of MapReduce as map + reduce "by key"
The mapper function doesn't just return a single value, but a list of key-value pairs possibly including multiple instances of the same key with different values.
Before calling the reducer, the execution engine groups all results by key


---

**Description:**

This slide explains the relationship between Python's `map` and `reduce` functions and the MapReduce programming model.

* **Conceptual Relationship:** The slide states that MapReduce can be understood as an extension of the `map` and `reduce` functions, but with a crucial difference:  MapReduce operates "by key."  This means the mapper function produces key-value pairs, and the reducer function operates on groups of values associated with the same key.
* **Mapper Function Behavior:** The slide emphasizes that the mapper function in MapReduce doesn't just return a single value for each input element. Instead, it returns a list of key-value pairs.  This is a key distinction from the simple `map` function in Python, which applies a function to each element and returns a new list of the same length.  The mapper function in MapReduce can produce multiple key-value pairs for a single input, and these pairs might have the same key but different values.
* **Grouping by Key:** The slide highlights that before the reducer function is called, the execution engine groups all the results by key.  This grouping is essential for the reducer function to operate on related data.

**Overall:** The slide provides a conceptual bridge between the familiar Python `map` and `reduce` functions and the more complex MapReduce model.  It emphasizes the key difference in how the mapper function behaves in MapReduce, producing key-value pairs, and the crucial grouping step performed by the execution engine before the reducer function is applied.
