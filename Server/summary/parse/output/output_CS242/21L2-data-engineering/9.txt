# Slide 9

# Cluster Computing Challenges

Cheap nodes fail, especially when you have many
* Mean time between failures (MTBF) for 1 node = 3 years
* MTBF for 1000 nodes = 1 day
* Solution: Build fault tolerance into system

Commodity network = low bandwidth
* Solution: Push computation to the data

Programming distributed systems is hard
* Solution: Restricted programming model
users write data-parallel "map" and "reduce" functions
system handles work distribution and failures

**Description of the slide:**

This slide, part of a lecture on Intro to Data Science, discusses the challenges of cluster computing.  It's a bulleted list format, highlighting the difficulties and potential solutions.

* **Content:** The slide focuses on three main challenges:
    * **Node Failures:**  The high failure rate of individual nodes in a large cluster is a significant problem, especially when dealing with thousands of nodes.  The example of a 1000-node cluster having a 1-day MTBF (Mean Time Between Failures) highlights the frequency of failures.
    * **Network Bandwidth:**  Commodity networks often have limited bandwidth, which can be a bottleneck in cluster computing.
    * **Distributed Programming:**  Writing programs that can efficiently distribute tasks across a large cluster of machines can be complex.

* **Purpose:** The slide is designed to introduce the concepts of fault tolerance, pushing computation to the data, and restricted programming models as solutions to these challenges.  It's meant to prepare students for the complexities of working with large-scale distributed systems.

* **Visuals:** There are no figures or images on this slide.  The content is entirely text-based, focusing on the description of the challenges and potential solutions.
