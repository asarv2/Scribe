# Slide 6

# How to improve efficiency for big data

If your data fits on a single machine (even on disk)

* Think about how you can design an efficient single-machine solution
* Unless you have exceptional circumstances, it is rarely faster to use multiple machines

Speed(cache) > Speed(RAM) > Speed(disk) > Speed(network)

**Description of the slide:**

This slide, part of a lecture on Intro to Data Science, discusses strategies for optimizing big data processing efficiency.

* **Content:** The slide presents a two-pronged approach to improving efficiency.  First, it advises that if the data fits on a single machine, the focus should be on designing an efficient single-machine solution.  Second, it emphasizes that using multiple machines is generally not faster unless there are specific, unusual circumstances.  The slide also highlights the relative speeds of different data storage mechanisms (cache, RAM, disk, network).
* **Visuals:**
    * **Diagram 1 (Left):** This diagram depicts a simplified computer architecture.  A CPU (Central Processing Unit) is shown with a connection to a cache memory, and then to RAM (Random Access Memory).  A hard drive (disk) is also shown.  The diagram is meant to illustrate the hierarchy of data access speeds, with cache being the fastest and network being the slowest.  The relative sizes of the components are not to scale, but the connections are meant to show the flow of data.
    * **Diagram 2 (Right):** This diagram shows a network of computers connected to a central server.  The computers are represented as individual desktop-style computers, and the server is a rack of servers.  The diagram is meant to illustrate the concept of using multiple machines for processing data, but also the added complexity and potential overhead of network communication.  The diagram is not meant to be a precise representation of a specific network architecture, but rather a general illustration of the concept.

* **Purpose:** The slide's purpose is to guide students toward understanding the trade-offs between single-machine and multi-machine solutions for big data processing.  The diagrams are meant to visually reinforce the concept of data access speed and the potential overhead of using multiple machines.  The relative speeds of the different components are meant to emphasize the importance of choosing the most efficient method for the given data size.
