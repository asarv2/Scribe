# Slide 13

# Abstracting map+reduce

Process can be decomposed into to the mapper function, the reducer function and the
execution engine (the supporting code that actually calls the map and reduce functions)

To use this framework, the programmer only needs to implement the mapper and the
reducer function—the execution engine can use whatever method it wants to actually
compute the result

The mapper function is inherently parallel, allowing execution in separate threads/machines

In many cases, the reduce step can also be carried out incrementally


---

**Description of the slide:**

This slide, part of a lecture on Intro to Data Science, discusses the abstraction level of the MapReduce framework.  It explains that the MapReduce process can be broken down into three components: the mapper function, the reducer function, and the execution engine.  The programmer only needs to implement the mapper and reducer functions; the execution engine handles the details of distributing the work and combining the results.  The slide emphasizes the inherent parallelism of the mapper function, which allows for efficient execution across multiple threads or machines.  It also notes that the reducer step can often be performed incrementally, further improving efficiency.  There are no figures on this slide.  The content is entirely text-based, focusing on the conceptual description of the MapReduce abstraction.
