# Slide 27

MPI weaknesses
MPI is extremely powerful but has some notable limitations
* It's complicated: programs need to explicitly manage data, synchronize threads, etc
* It's brittle: if machines die suddenly, can be difficult to recover (unless explicitly handled by the program, making them more complicated)


**Description of the slide:**

This slide, part of a lecture on Intro to Data Science, discusses the limitations of the Message Passing Interface (MPI).  It highlights two key weaknesses: complexity and brittleness.

* **Complexity:** The first point states that MPI programs are complex because they require explicit management of data and synchronization of threads.  This contrasts with higher-level abstractions like MapReduce, which handle these details automatically.
* **Brittleness:** The second point emphasizes that MPI programs are brittle.  If a machine in the distributed system fails unexpectedly, recovering from the failure can be difficult without explicit handling within the program.  This is in contrast to MapReduce, which often has built-in fault tolerance mechanisms.

**Overall:** The slide is designed to contrast the power of MPI with its inherent complexities and potential for failure in a distributed environment.  It sets the stage for discussing alternative, potentially simpler, distributed computing paradigms.
