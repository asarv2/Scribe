# One-to-Many Relationship

We have already seen a one-to-many relationship: one role can be shared by many people, denoted as follows:

| ID | Last Name | First | RoleID |
|---|---|---|---|
| 1 | Bergstrom | Anthony | 1 |
| 2 | Purdue | Peter | 2 |
| 3 | Doe | John | 3 |
| 4 | Smith | Jane | 3 |

| RoleID | Role |
|---|---|
| 1 | Instructor |
| 2 | TA |
| 3 | Student |

---

**Description of the Slide:**

This slide, part of a lecture on Introduction to Data Science, illustrates a one-to-many relationship in a relational database.  The title "One-to-Many Relationship" clearly indicates the topic.  The text above the tables explains that this type of relationship has already been seen in previous examples, where one role can be held by multiple people.  The slide presents two tables side-by-side.  The table on the left, labeled "Person," contains data with columns for "ID," "Last Name," "First," and "RoleID."  The table on the right, labeled "Role," contains data with columns for "RoleID" and "Role."  The data in both tables is structured in rows and columns, with each row representing a record and each column representing an attribute.  The data includes sample information about individuals and their roles (e.g., Bergstrom Anthony is assigned RoleID 1, which corresponds to Instructor).  The purpose of this slide is to visually demonstrate a one-to-many relationship, where one role (in the "Role" table) can be held by multiple people (in the "Person" table).  The tables are formatted with clear column headers and data entries, making the one-to-many relationship between the tables easily visible.  The layout is designed to visually represent the concept of a one-to-many relationship and its common occurrence in relational database design.  There is a visual representation of the relationship between the two tables, with an arrow from the "Person" box to the "Role" box, indicating that multiple people can have the same role.
