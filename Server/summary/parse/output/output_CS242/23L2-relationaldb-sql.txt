Database: A database consists of a set of named relations (aka tables)

# Slide 14

# Database Schema vs Instance

Precise contents a database generally vary over time

Database Schema: The "structure" of the database in terms of its constituent tables and the organization of each table in terms of its attributes and the relationships between tables; remains fixed over time

Database Instance: Any specific collection of values populating the DB that conforms to the schema; changes as DB is modified

RDBMS: Relational database management system (system software for creating and managing databases)


---

**Description of the Slide:**

This slide, part of a lecture on Introduction to Data Science, explains the difference between a database schema and a database instance.  The title "Database Schema vs Instance" clearly indicates the topic.  The text defines both concepts:

* **Database Schema:** This is the structure of the database, including the tables, their attributes (columns), and the relationships between the tables.  It's the blueprint or design of the database, which remains constant over time.

* **Database Instance:** This is the actual data contained within the database at a specific point in time.  It's the current state of the data, which can change as the database is updated or modified.

* **RDBMS:**  This stands for Relational Database Management System, which is the software used to create and manage databases.

The slide is purely textual, with no figures.  The content is concise and clearly explains the fundamental difference between the static structure (schema) and the dynamic data (instance) of a relational database.  The purpose of this slide is to establish a foundational understanding of these key database concepts.
